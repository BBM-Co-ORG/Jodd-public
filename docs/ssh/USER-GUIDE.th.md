# เก็บโน้ตไว้บนเซิร์ฟเวอร์ของคุณเอง (SSH)

คู่มือนี้อธิบายบัญชี SSH: เซิร์ฟเวอร์ต้องมีอะไร เพิ่มบัญชีใน Jodd อย่างไร
และดูแลต่ออย่างไร โน้ตบนเซิร์ฟเวอร์ SSH เป็นไฟล์ Markdown ธรรมดาในโฟลเดอร์ที่คุณเลือก
Jodd ทุกเครื่องที่เชื่อมต่อ และโปรแกรมใดก็ตามที่คุณรันบนเซิร์ฟเวอร์ จะทำงานกับไฟล์ชุดเดียวกัน

**บัญชีนี้ไม่ซิงก์กับ Apple Notes** บัญชี SSH เป็นที่เก็บของ Jodd เอง
ถ้าต้องการใช้กับ Apple Notes ให้เพิ่มบัญชี Gmail, Outlook หรือ iCloud แทน

รายละเอียดภายใน (รูปแบบไฟล์ การชนกันของการแก้ไข สคริปต์) อยู่ใน
[BACKEND-SSH.md](../BACKEND-SSH.md) ส่วน AI host ซึ่งใช้ SSH เหมือนกัน มี
[คู่มือของตัวเอง](../ai-host/USER-GUIDE.th.md)

## เซิร์ฟเวอร์ต้องมีอะไร

- เซิร์ฟเวอร์ Linux, BSD หรือ macOS ที่คุณเข้าผ่าน SSH ได้ และมีบัญชีผู้ใช้อยู่
  เซิร์ฟเวอร์ SSH ของ Windows โดยตรงใช้ไม่ได้ เพราะไม่มี `sh`
- เครื่องมือ command line ทั่วไป ซึ่งเซิร์ฟเวอร์เกือบทุกเครื่องมีอยู่แล้ว:
  `sh`, `find`, `awk`, `sed`, `base64`, `mktemp`, `ln`, `mkdir`, `mv`, `rm`,
  `stat` และ `sha256sum` หรือ `shasum`

**ถ้าทำได้ ให้ใช้บัญชีแยกไว้สำหรับ Jodd โดยเฉพาะ** เช่นบัญชีชื่อ `jodd`
key ของ Jodd รัน shell ได้ในฐานะบัญชีที่มันเข้าสู่ระบบ ซึ่งโน้ตจำเป็นต้องใช้
ถ้าใช้บัญชีแยก มือถือที่หายไปจะเข้าถึงได้แค่โน้ต ไม่ใช่ทุกอย่างบนเซิร์ฟเวอร์

## บัญชี SSH มีสองแบบ

| | **Add SSH Server** | **Add SSH Server (advanced)** |
|---|---|---|
| เหมาะกับ | ทุกคนที่มีที่อยู่เซิร์ฟเวอร์และชื่อผู้ใช้ | คนที่ใช้ `ssh` ใน terminal อยู่แล้ว |
| Key | Jodd สร้าง key ของตัวเองสำหรับเครื่องนี้ | key ของคุณเอง จาก `ssh-agent` และ `~/.ssh/config` |
| Desktop | ได้ | ได้ |
| Android | ได้ | ไม่ได้ |

ทั้งสองแบบอยู่ที่ **Settings › Accounts** ถ้าเพิ่งติดตั้งใหม่ หน้าจอแรกมีปุ่ม
**Start with an SSH server** ซึ่งเปิด **Add SSH Server** ส่วนที่เหลือของคู่มือนี้พูดถึง **Add SSH Server**

## Add SSH Server

**หน้าจอ 1, Connect to your server** กรอก:

- **Server address**: เช่น `box.example.com` ถ้าเซิร์ฟเวอร์ไม่ได้ใช้พอร์ต 22 ให้เติม `:2222`
- **Username**: บัญชีบนเซิร์ฟเวอร์
- **How you sign in**: เลือกหนึ่งในสามวิธีด้านล่าง
- **Notes folder on the server**: `~/Jodd-Notes` ถ้าไม่ต้องการโฟลเดอร์อื่น
  ถ้ายังไม่มี Jodd จะสร้างให้
- **Name in the sidebar (optional)**

กด **Continue**

**หน้าจอ 2, Is this your server?** Jodd แสดงตัวตนของเซิร์ฟเวอร์ (fingerprint)
ถ้าผู้ให้บริการโฮสติ้งแสดง fingerprint ไว้ในหน้าควบคุมหรืออีเมล ให้ตรวจว่าตรงกัน
แล้วกด **Trust and connect**

ไม่ว่าจะเลือกวิธีไหน สุดท้าย Jodd จะมี **key ของตัวเองสำหรับเครื่องนี้**
Jodd ไม่เก็บรหัสผ่าน และไม่เก็บ key ของคุณ

### Password

กรอกรหัสผ่านของบัญชี Jodd ใช้รหัสผ่านครั้งเดียวเพื่อเพิ่ม key ของตัวเองบนเซิร์ฟเวอร์
แล้วไม่ใช้อีกเลย ใช้ได้ทั้ง desktop และ Android

ถ้าเซิร์ฟเวอร์ไม่รับรหัสผ่าน (*This server only accepts keys*)
ให้ย้อนกลับไปเลือก **Run a command on the server** หรือ **Key file** บน desktop

### Run a command on the server

ไม่ต้องกรอกรหัสผ่านใน Jodd ใช้ได้ทั้ง desktop และ Android
รวมถึงเซิร์ฟเวอร์ที่รับเฉพาะ key

1. หลังกด **Trust and connect** Jodd จะแสดง **Add Jodd's key on your server**
   พร้อมคำสั่งหนึ่งบรรทัด กด **Copy**
2. เข้าสู่ระบบเซิร์ฟเวอร์ตามที่คุณทำปกติ **ด้วยผู้ใช้คนเดียวกับที่กรอกในหน้าจอ 1**
   ไม่ใช่ root (เว้นแต่ผู้ใช้นั้นคือ root) วางคำสั่งแล้วรัน ใช้ bash, zsh หรือ sh
   ถ้า shell ของคุณเป็น fish หรือ csh ให้พิมพ์ `sh` ก่อน
3. คำสั่งจะพิมพ์ `Jodd's key was added.` กลับมาที่ Jodd แล้วกด **I've run it**

Jodd ตรวจว่า key ของตัวเองใช้ได้ แล้วจึงสร้างโฟลเดอร์โน้ตและบัญชี
ถ้าขึ้นว่า *The server doesn't accept Jodd's key yet* แปลว่าคำสั่งยังไม่ได้รัน
หรือรันด้วยผู้ใช้คนอื่น ให้รันอีกครั้งด้วยผู้ใช้ที่ถูกต้อง แล้วกด **I've run it** อีกครั้ง
ระหว่างนั้น Jodd ยังคงหน้าจอและคำสั่งไว้ให้

คำสั่งนี้เพิ่มบรรทัดเดียวต่อท้าย `~/.ssh/authorized_keys` เท่านั้น
และตรวจก่อนว่ากำลังรันด้วยผู้ใช้ที่ถูกต้อง ถ้าไม่ใช่จะไม่ทำอะไร
บรรทัดนั้นจำกัดสิทธิ์ของ key ไว้: ไม่มี port forwarding ไม่มี agent หรือ X11 forwarding และไม่มี terminal

กด **Back** จากหน้าจอนี้จะลบ key ที่ Jodd สร้างไว้ และลบออกจากเซิร์ฟเวอร์ด้วยถ้า Jodd ตรวจไปแล้ว

### Key file (desktop)

เลือก private key ที่ผู้ให้บริการโฮสติ้งให้มา และ
**Passphrase (only if the key needs one)** Jodd ใช้ key นั้น **ครั้งเดียว**
เพื่อเพิ่ม key ของตัวเอง และไม่เก็บสำเนา key ของคุณไว้ key แบบ RSA ใช้กับเซิร์ฟเวอร์รุ่นปัจจุบันได้
key แบบ PuTTY (`.ppk`) ต้อง export เป็นรูปแบบ OpenSSH ด้วย PuTTYgen ก่อน

บน Android ยังใช้ key file ไม่ได้ ให้ใช้ **Run a command on the server** หรือ **Password**

## การดูแลต่อ

### ใช้บนอีกเครื่อง

แต่ละเครื่องมี key ของตัวเอง บนเครื่องใหม่ ให้เพิ่มเซิร์ฟเวอร์เดิมและ
**Notes folder on the server** เดิมด้วย **Add SSH Server** ใช้วิธีไหนก็ได้ในสามวิธี
ถ้าเซิร์ฟเวอร์ไม่รับรหัสผ่านแล้ว ให้ใช้ **Run a command on the server**
จากนั้นทั้งสองเครื่องจะทำงานกับโน้ตชุดเดียวกัน

### โฟลเดอร์โน้ตที่สองบนเซิร์ฟเวอร์เดียวกัน

เพิ่มเซิร์ฟเวอร์เดิมอีกครั้งโดยใส่ **Notes folder on the server** อื่น
แต่ละโฟลเดอร์เป็นบัญชีแยกที่มี key ของตัวเอง การลบบัญชีหนึ่งจึงไม่ตัดอีกบัญชี
Jodd ไม่ยอมเพิ่มโฟลเดอร์ที่เป็นบัญชีอยู่แล้วบนเครื่องนี้

### ปิดการเข้าสู่ระบบด้วยรหัสผ่านบนเซิร์ฟเวอร์

ปิดได้เลย Jodd ใช้ key ของตัวเองอยู่แล้วและไม่ต้องใช้รหัสผ่านอีก
หลังจากนั้นให้ตั้งเครื่องใหม่ด้วย **Run a command on the server** (หรือ **Key file** บน desktop)

### เปลี่ยนรหัสผ่านของบัญชีบนเซิร์ฟเวอร์

ไม่ต้องทำอะไรใน Jodd key ของ Jodd ยังใช้ได้

### ลบบัญชี

กด **Remove** ข้างบัญชีในรายการบัญชีของ sidebar หรือ **Remove account** ในหน้าตั้งค่าของบัญชีนั้น
ช่อง **Also remove Jodd's key from the server** ติ๊กไว้ให้แล้ว
Jodd ลบบัญชีทันที แล้วลบบรรทัด key ของตัวเองบนเซิร์ฟเวอร์อยู่เบื้องหลัง
โน้ตของคุณยังอยู่บนเซิร์ฟเวอร์ครบ มีแค่สิทธิ์เข้าถึงของเครื่องนี้ที่หายไป

ถ้าตอนนั้นติดต่อเซิร์ฟเวอร์ไม่ได้ บรรทัดนั้นจะยังอยู่ ไม่เป็นอันตราย
แต่คุณลบเองได้ (ดูหัวข้อถัดไป)

### เครื่องที่หายหรือเลิกใช้แล้ว

ลบ key ของเครื่องนั้นบนเซิร์ฟเวอร์: เปิด `~/.ssh/authorized_keys` ของบัญชีที่เก็บโน้ต
แล้วลบบรรทัดของเครื่องนั้น บรรทัดของ Jodd ลงท้ายด้วย `jodd-` ตามด้วยตัวอักษรหรือตัวเลขแปดตัว
หนึ่งบรรทัดต่อหนึ่งเครื่องต่อหนึ่งโฟลเดอร์ ถ้าแยกไม่ออกว่าบรรทัดไหนเป็นเครื่องที่หาย ให้ลบทุกบรรทัด `jodd-`
แล้วตั้งเครื่องที่เหลือใหม่ (ลบบัญชีใน Jodd แล้วเพิ่มกลับ **Run a command on the server** ใช้เวลาประมาณหนึ่งนาที)

### เมื่อ Jodd เข้าสู่ระบบไม่ได้

ถ้า Jodd บอกว่าเซิร์ฟเวอร์ปฏิเสธ key ของมัน มักเป็นเพราะบรรทัดนั้นถูกลบออกจากเซิร์ฟเวอร์
หรือกฎการเข้าสู่ระบบของเซิร์ฟเวอร์เปลี่ยนไป ให้ลบบัญชีแล้วเพิ่มกลับ
โน้ตที่ซิงก์แล้วยังอยู่บนเซิร์ฟเวอร์

### เมื่อเซิร์ฟเวอร์ถูกสร้างใหม่หรือย้ายเครื่อง

เซิร์ฟเวอร์ที่สร้างใหม่มีตัวตนใหม่ และ Jodd จะไม่เชื่อมต่อกับเซิร์ฟเวอร์ที่ตัวตนเปลี่ยนไป
(*This server's identity is different from when you trusted it*)
**ถ้าคุณไม่ได้สร้างใหม่หรือย้ายเซิร์ฟเวอร์ ให้หยุดก่อน** ตัวตนที่เปลี่ยนอาจหมายถึงมีคนดักกลางการเชื่อมต่อ
ให้สอบถามผู้ให้บริการโฮสติ้งก่อน ตอนนี้ยังไม่มีหน้าจอ "เชื่อถือตัวตนใหม่" ให้ลบบัญชีแล้วเพิ่มกลับ และตรวจ fingerprint ใหม่ในหน้าจอ 2
ถ้าคุณแก้ไขโน้ตบนเครื่องนี้หลังการซิงก์ครั้งล่าสุด ให้คัดลอกข้อความนั้นเก็บไว้ก่อน
เพราะ Jodd ส่งไปยังเซิร์ฟเวอร์ที่มันไม่ยอมเชื่อมต่อไม่ได้

### โฟลเดอร์โน้ตหายไป

Jodd จะบอกว่า *the vault directory is missing on the server* ให้กู้คืนหรือสร้างโฟลเดอร์นั้นใหม่บนเซิร์ฟเวอร์
(พร้อมไฟล์จากข้อมูลสำรอง) แล้ว Jodd จะทำงานต่อได้
