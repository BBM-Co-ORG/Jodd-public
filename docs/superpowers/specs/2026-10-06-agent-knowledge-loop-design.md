# Agent knowledge loop — agents keep Jodd organized, Jodd makes agents better

Status: design approved in conversation 2026-10-06; this spec awaits review.
Scope of this document: the **whole loop at overview level**, and **Milestone 1
(F + B) in full detail**. Milestones 2–4 get their own detailed spec when they
start, informed by what Milestone 1 measures.

## 1. Problem and intent

Jodd already holds the user's knowledge, and `jodd-mcp` already lets an agent
search it and write into one allowlisted folder (`Notes/__Claude__`). Neither
side improves the other:

- Agents do not consult Jodd unless told to. `jodd-mcp` sends no server
  `instructions` ([main.rs:319](../../../jodd-mcp/src/main.rs)), so an agent
  sees tool descriptions — *what* a tool does — and nothing says *when* Jodd
  matters.
- What an agent learns (a decision, a lesson, the user's preference) dies with
  its session, or lives in one tool's private memory (Claude Code's memory
  directory) that no other agent and not the user's phone can see.
- The user's existing notes have problems they cannot describe as a command:
  duplicates (measured 2026-10-05: three notes from one YouTube video, one of
  which covered 16% of it), misfiled notes, near-duplicate folders.

**Intent (stated by the user):** agents put knowledge into Jodd, organize it,
and draw on it to work better, and each round improves the next — for coding
work *and* research/business work, in **one shared knowledge base**.

**Success:** an agent doing real work today finds and uses what was saved last
month without being told where it is, and leaves Jodd better organized than it
found it — while the user stays in control of their own notes.

## 2. Decisions (from the 2026-10-06 conversation)

| # | Question | Decision |
|---|---|---|
| D1 | Which work | Both coding (Claude Code, thClaws) and research/business (Claude Desktop); one shared knowledge base |
| D2 | What an agent may change | Per folder: agents fully own an **agent workspace** (`Notes/__Agent__/`); the user's own folders get **append-only** changes or **proposals the user approves** |
| D3 | What an agent may read | Everything except **folders the user hides**; one list, the same for every agent |
| D4 | How agents remember to use Jodd | **Both**: server `instructions` for every MCP client, plus a **session-start briefing** through a hook where the client has hooks |
| D5 | Workspace structure | Karpathy's LLM Wiki layers (`Conventions` / `Index` / `Log`) with Basic Memory's **topic pages holding `[kind]` lines**, one page per topic |
| D6 | Who creates the structure | **Jodd**: a skeleton on enable, then tools that know the layout place everything — agents never compose a path |
| D7 | How project / area / kind are chosen | Kind: closed enum. Project (coding): **derived from the repo**. Area: must be an existing name or an explicit new one; unsure → `Inbox` |
| D8 | Organizing existing notes | Jodd **finds** problems deterministically (`health_report`), the agent **decides**, the user **approves** — through a **review UI in the app from the start** |
| D9 | Build order | **F → B → C → A → D**: the smallest complete memory loop first, to test the riskiest assumption (that agents will actually use Jodd) cheaply |

## 3. Prior art adopted

**Karpathy, "LLM Wiki"** ([gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)),
already the framing of [LLM-WIKI-GRAPHIFY-ROADMAP.md](../../LLM-WIKI-GRAPHIFY-ROADMAP.md):

| LLM Wiki | Jodd |
|---|---|
| raw sources, immutable | the `Source (verbatim)` block every ingest already writes |
| the wiki, LLM-maintained | `Notes/__Agent__/` |
| schema file (CLAUDE.md / AGENTS.md) | the `Conventions` note — user-editable, so changing a rule is editing a note |
| `index.md`: every page, one-line summary | the `Index` note, **generated by Jodd** |
| `log.md`, append-only, `## [2026-04-02] ingest \| Article` | the `Log` note, same prefix format |
| ingest / query / lint | Capture (A) / Recall (B) / Curate (C) |
| lint: contradictions, stale claims, orphans, missing pages, missing cross-references | `health_report` categories (C) |
| ingest **updates existing pages**, not only adds one | Capture (A) updates the related topic pages |

**Basic Memory** ([knowledge format](https://docs.basicmemory.com/concepts/knowledge-format)):
facts are **lines with a bracketed category inside a topic page**
(`- [decision] Use Postgres for primary storage`), and relations are
`relation_type [[Page]]`. Adopted because one page per topic produces far
fewer notes than one note per fact, makes duplicates rarer, and reads cleanly
on an iPhone.

**Claude Code's memory**: every memory has a one-line description, and an
index is loaded into every session — the shape of the briefing (§5.6).

**Not adopted, and why:**
- **YAML frontmatter** (Basic Memory, Claude Code memory, OKF): it shows as
  raw text in Apple Notes; Jodd already ruled it out for note bodies. Metadata
  lives in SQLite, tags, or a short readable line.
- **"The LLM owns the whole wiki"** (Karpathy): true only inside
  `Notes/__Agent__/`, per D2.
- **Files on disk**: Jodd notes are Gmail / iCloud / Exchange / local records,
  so `index.md` and `log.md` become notes.

**What none of them solve, and Jodd must:** approval of changes to
human-owned notes, a merge procedure for duplicates, Apple round trip, and
several accounts with different write capabilities.

## 4. The loop at overview level

```
          ┌──────────── B Recall ────────────┐
          │ briefing at session start,       │
          ▼ search / read_note during work   │
      [ agent works ]                  [ Jodd knowledge ]
          │                                  ▲
          │ A Capture: ingest sources        │
          │ B remember: decisions, lessons   │
          └──────────────────────────────────┘
                       ▲          │
     C Curate: health_report → proposals → user approves in app
     D Learn: approvals, rejections and user edits refine Conventions / About me
```

| Milestone | Group | Contents | Detailed spec |
|---|---|---|---|
| **M1** | **F Foundation** | hidden folders, `read_note`, server `instructions`, agent workspace skeleton (`Conventions`, `Index`, `Log`, `About me`) | **this document, §5** |
| **M1** | **B Recall + basic memory** | `remember`, `list_topics`, project detection, `jodd-mcp brief` + hook | **this document, §5** |
| M2 | C Curate | `health_report`; one execution engine in `jodd_lib` for move / merge / link across all backends; a proposals store (SQLite, mirrored to a readable synced note); **a review screen in the app** (desktop + Android) with side-by-side merge preview, approve-and-apply | later |
| M3 | A Capture | `find_source`, `fetch_source` (paged), `list_tags`, `save_ingested_note` (the app's own ingest body), MCP prompt `ingest_key_points` generated from `prompt.rs`; ingest also appends to related topic pages | later |
| M4 | D Learn | rejected proposals and user edits as signals; agent-proposed `Conventions` / `About me` updates | later; least defined |

Decisions already made for later milestones, recorded so they are not
re-litigated: M2's review UI ships with M2, not after it (the execution engine
is required either way and is the hard part; approving a merge without seeing
it is approving blind). M2 proposals cannot live only in SQLite — it does not
sync, so a proposal made on the Mac would not reach Android.

## 5. Milestone 1 in detail (F + B)

### 5.1 The agent workspace

**Location.** `Notes/__Agent__/` in **one home account** the user picks. The
`__name__` leaf makes it a `system_workflow` folder (gotcha #4: kind is derived
from the leaf). One home account, because the knowledge base is shared (D1);
reads still span every account (D3).

**Eligible home accounts:** any account whose `Capabilities::for_backend(..)
.writes` has `notes && folders` true. That excludes Microsoft (folder writes
are permanently `false`). If the user later removes the home account, the
workspace setting is cleared and `remember` refuses (§5.9) until a new one is
chosen.

**Enabling** (Settings → *Agent workspace*): choose the home account → Jodd,
locally and synchronously (local-first doctrine), creates:

```
Notes/__Agent__/
  Conventions     the rules below, in plain language; the user may edit it
  Index           generated (§5.7) — "do not edit, Jodd rewrites this"
  Log             append-only (§5.7)
  About me        empty page; remember places preference lines here (§5.4 rule 3)
  Projects/       folder
  Areas/          folder
  Inbox           page for observations with no topic
```

and records the workspace in `mcp_write_scope.json` — a top-level
`"agent_workspace": {"account_id": "…"}` plus `Notes/__Agent__` in that
account's `allowed_folders`. One file, because the app and `jodd-mcp` both
need it; its model moves from `jodd-mcp/src/scope.rs` into `jodd_lib`
(`mcp_scope.rs`) so there is one reader of the format, not two. **This is the first time the app writes that file**;
today it is hand-edited only. The app must preserve every other key and entry
it does not understand, write atomically (temp file + rename, as `set_ai_limits`
does), and never remove an entry it did not add.

The existing `Notes/__Claude__` is left untouched. `Conventions` mentions it
so an agent knows older notes may be there; moving them is an M2 proposal.

### 5.2 Page format

A **page** is an ordinary note. Its title is the topic name. Body:

```
<one-line summary of the topic>            ← line 1, used by Index and briefing

- [decision] Chunk Key points instead of truncating at 60k (2026-10-05 · claude-code)
- [lesson] A 'clean in Notes.app' check minutes after a write proves nothing (2026-08-27 · claude-code)
- [preference] Ask before force-pushing, every time (2026-09-02 · claude-code)
- relates_to [[YouTube services]]
```

- **Kinds (closed enum, enforced by the tool's JSON Schema):** `decision`,
  `lesson`, `preference`, `fact`, `source`. Adding a kind is a code change on
  purpose. A misjudged kind is cheap — it is a word on a line, not a location.
- **Provenance** on every line: date and the MCP client's self-reported name
  (`clientInfo.name`). That name is a label for the user, not an identity.
- **Relations:** `relation_type [[Page title]]`; the existing deriver turns
  `[[...]]` into `mentions` edges, so `note_connections` sees them unchanged.
- Lines are appended in M1. Grouping, rewording, splitting a page that grew
  too long and resolving contradictions are M2 Curate work.

### 5.3 Hidden folders (D3)

`mcp_write_scope.json` gains an optional per-account `hidden_folders` list:

```json
{ "accounts": { "gmail:kaiwan@bbmedia.co.th": {
    "allowed_folders": ["Notes/__Agent__", "Notes/__Claude__"],
    "hidden_folders": ["Notes/Personal", "Notes/BBMedia/Clients"] } } }
```

- Matching uses `jodd_lib::folder_scope::matches(label, hidden, Mode::Subtree)`
  — the shared matcher (gotcha #33). No new copy of the rule.
- **Every read path** excludes hidden notes: `search_notes`, `note_connections`
  (both directions — a visible note's backlink from a hidden note is dropped),
  `list_tasks`, `read_note`, `list_topics`, `brief`. A conformance test
  enumerates the tool router so a future read tool cannot skip the filter.
- A hidden note is reported exactly as a missing one ("no such note"). Saying
  "hidden" would confirm it exists.
- **Hidden beats allowed:** a folder both allowed and hidden is not writable.
  The workspace itself cannot be hidden (Settings refuses).
- Backward compatible: a file without `hidden_folders` hides nothing, which is
  today's behavior. An **unparseable** file now refuses reads too
  (fail-closed), where today it only refused writes.
- Settings → *Agent workspace* lists the account's folders with a *Hide from
  agents* toggle, written through the same safe-write path as §5.1.

### 5.4 New and changed MCP tools

**`read_note(account_id, uuid, offset?)`** → `{title, folder, markdown, total_chars, next_offset?}`.
Fills the gap `search_notes` documents ("there is currently no tool to look up
a note's complete content"). Body converted with the existing
`backend::ssh::mdconv::html_to_md`; when that returns `None`, tag-stripped text
with a note saying so. Pages of 20 000 characters with `next_offset`, so a
125 000-character ingest note cannot flood a context. The verbatim source block
is excluded by default (`include_source: true` to read it).

**`remember(kind, text, project?, area?, new_area?, relates_to?)`** → `{page, line}`.
The only way an agent writes knowledge in M1. Placement rules:

1. `area` given → `Areas/<area>`. It must match an existing page
   (case-insensitive). If not, and `new_area` is not `true`, it is **refused**
   with up to three nearest names ("No area 'Youtube'. Did you mean
   'YouTube services'?"), using trigram similarity.
2. else `project` given, or derived (§5.5) → `Projects/<project>`, created on
   first use. A project page needs no `new_*` flag because its name comes from
   the repo, not from the model.
3. `kind = preference` with no topic → `About me`.
4. otherwise → `Inbox`.

One `remember` call makes three writes, in this order: append the line to the
page (the write that matters), regenerate `Index`, append to `Log` (§5.7). They
are **not** one SQLite transaction — `apply_local_edit_versioned` edits one
note and re-derives its FTS, tags and edges, and a multi-note transaction would
mean restructuring `db.rs` for little gain. Instead `Index` is regenerated
whole from the pages on every write, so a failed regeneration is repaired by
the next `remember`, and `Log` is advisory. Each write goes through the
existing compare-and-swap retry (`write_with_retry`) and the cross-process
safety of the MCP write spec §4.5. Writing to Gmail-type backends
happens when the app's sync worker next runs, exactly as `create_note` today.

**`list_topics()`** → projects and areas with their one-line summaries and
line counts. It plays the role for areas that the tag vocabulary plays for
Extract (roadmap #0).

**`list_accounts`** additionally returns `agent_workspace: {account_id, folder}`,
or `null` when it is not enabled.

### 5.5 Project detection

Order, first hit wins:
1. an explicit `project` argument;
2. MCP **roots** (the client's workspace folders): the git remote's repository
   name (`BBM-Co-ORG/Jodd` → `Jodd`), else the folder name;
3. none → `remember` places the line by §5.4 rules 3–4.

**Unverified:** whether Claude Code, Claude Desktop and thClaws send roots, and
whether `rmcp` 2 exposes `list_roots` on the server side. The first
implementation step is a probe (§5.10). If a client sends no roots, its agent
passes `project` itself, and `instructions` tell it to.

### 5.6 Session-start briefing

`jodd-mcp brief --cwd <path> [--max-chars 8000]` prints Markdown to stdout:

1. `About me` (whole page, it is short by design);
2. the project's page, detected from `<path>` as in §5.5;
3. the project's last 10 `Log` entries;
4. one line: how to search Jodd for more.

The output is bounded by `--max-chars`, cutting the page body before the
`About me` lines. Nothing in a hidden folder is included. It is a
subcommand of the existing binary, so it shares the DB, scope and matcher code
— not a second program that could drift.

**Claude Code** (documented in `Conventions` and the README), as a SessionStart
hook whose stdout becomes session context:

```json
{ "hooks": { "SessionStart": [ { "hooks": [
  { "type": "command", "command": "jodd-mcp brief --cwd \"$CLAUDE_PROJECT_DIR\"" } ] } ] } }
```

Unverified: the exact variable and output contract on the user's Claude Code
version, and whether thClaws has an equivalent hook (§5.10). Claude Desktop
has no hooks; it relies on `instructions` alone (D4).

### 5.7 Index and Log

Both are **generated by Jodd**, never by the model, so they cannot drift from
the pages:

- `Index`: `- [[<page>]] — <line 1 of the page>` grouped under `Projects`,
  `Areas`, then `About me` and `Inbox`. Rewritten in the same transaction as
  any `remember`.
- `Log`: one line appended per write, in Karpathy's parseable form:
  `## [2026-10-06] remember | Projects/Jodd | decision | claude-code`.
  The Log is what §5.11 counts.

### 5.8 Server instructions

`get_info` gains `instructions`, at most 2 000 characters, built from a
template plus live facts (whether the workspace exists, its location, the kind
list). Draft:

```text
Jodd is the user's personal knowledge base, shared by all of their agents:
lessons, decisions, preferences, sources and project context.

Before non-trivial work, check Jodd: search_notes for the project, topic or
person involved; read_note for the full text. Prefer what Jodd records over
your own assumptions, and say so when they conflict.

When you learn something worth keeping — a decision and its reason, a lesson,
a user preference, a useful source — call remember. Pass project (the repo
name) for coding work; pass an existing area for other work (list_topics).
If unsure, omit both; it goes to Inbox and is sorted later.

Outside the agent workspace, only append. Some folders are hidden from you by
the user; do not ask about them.
```

When the workspace is not enabled, the `remember` paragraph is replaced by one
sentence: "Agent memory is off; the user can enable it in Jodd Settings."

### 5.9 Error handling

| Situation | Behavior |
|---|---|
| `remember` with no workspace enabled | refused: "Agent memory is off — enable it in Jodd Settings → Agent workspace" |
| unknown area without `new_area` | refused with up to 3 suggestions; nothing written |
| kind not in the enum | refused by schema, listing the valid kinds |
| home account removed or no longer folder-capable | setting cleared; as "not enabled" |
| hidden / missing note in `read_note` | "no such note" (same text for both) |
| `mcp_write_scope.json` unparseable | every tool refuses with the parse error; nothing is read or written |
| concurrent writes (app + MCP, two agents) | existing compare-and-swap retry + MCP spec §4.5; `Index` is regenerated whole, so a lost race is repaired by the next write |
| `Index` or `Log` write fails after the line was appended | `remember` reports the line as saved and the follow-up failure as a warning; the line is never written twice |
| `brief` with no DB, or workspace off | prints nothing, exits 0 — a hook must never block a session from starting |

### 5.10 Testing

**Automated** (`cargo test --workspace`, `vitest`, CI gates as CLAUDE.md lists):
- hidden folders: every read tool, enumerated from the router; backlinks from
  hidden notes; hidden-beats-allowed; unparseable file fails closed; missing
  key hides nothing;
- `remember`: placement rules 1–4; refusal and suggestions (nothing written);
  provenance format; `Index` after a write lists every page exactly once;
- `Index` / `Log` regeneration is deterministic (same pages → same bytes);
- `read_note`: paging, `include_source`, the `html_to_md` fallback;
- `brief`: bound respected, hidden content absent, exits 0 when off;
- Settings: the safe write of `mcp_write_scope.json` preserves unknown keys
  and entries the app did not add (gotcha #28: mount the component to test
  identity and values in one reactive turn).

**Live** (gotcha #7 — documentation says what exists, only a run says what it
does), recorded in the PR:
1. Claude Code: are `instructions` shown; are roots sent; does the
   SessionStart hook inject the briefing.
2. Claude Desktop: are `instructions` shown; are roots sent.
3. thClaws: same three questions.
4. A note written by `remember` reaches Gmail and Apple Notes readable: the
   `[kind]` lines and `[[links]]` as plain text, no markup visible.

### 5.11 How M1 is judged

After two weeks of the user's normal work, from `Log` and the user's own
account:
- how many `remember` calls, from which clients, into which topics;
- how many sessions started with a briefing;
- at least three occasions where an agent used something saved earlier without
  being told where it was — the success statement in §1, observed rather than
  assumed.

If agents do not call `remember` or use the briefing, M2 starts by fixing that,
not by building Curate on top of an unused workspace.

## 6. Out of scope for M1

Merge, move and delete tools; proposals and the review UI (M2). Ingest tools
(M3). Learning from edits (M4). Per-agent read scopes (D3 chose one list).
Moving `Notes/__Claude__` content. An OKF export.

## 7. Open questions

1. Do the three clients send MCP roots? (§5.5, probed first.)
2. Does thClaws have a session-start hook? (§5.6.)
3. How long can a topic page get before Apple Notes or the editor struggles?
   Sets M2's page-split threshold.
4. `About me` is inside the workspace, so it cannot be hidden (§5.3) and every
   agent reads it in every briefing. Is that right for preferences that are
   personal rather than about work? Default yes; if not, M4 adds a
   work-only / personal split rather than an exception to §5.3.

## 8. M1 as built — live results and known limitations (2026-10-06)

**Live (UAT), on the user's machine and Gmail account:**

| Check (§5.10) | Result |
|---|---|
| Claude Code shows `instructions` | ✅ quoted verbatim by a headless session, both variants |
| Claude Code sends roots | ✅ `client claude-code: 1 root(s)`; `remember` with no project landed on `Projects/Jodd` |
| SessionStart hook injects the briefing | ✅ a session with no MCP server quoted the saved lesson; `brief` runs in 0.08 s |
| Hidden folder in search | ✅ `broker`: 4 results before, 1 after hiding `Notes/Personal` |
| Written page syncs and reads as plain lines | ✅ in Gmail, label `Notes/__Agent__/Projects` |
| Settings → enable, hide | ✅ driven in a debug `Jodd.app`; the scope file kept every prior entry |
| thClaws | ❌ not possible today: its hooks discard stdout (`thclaws-technical-manual/hooks.md`, fire-and-forget, `/dev/null`); `mcp.md` documents neither `instructions` nor roots. Needs thClaws changes, not Jodd's |
| Claude Desktop | not run: restarting it would end the session doing the UAT |

UAT found two defects that tests had not: the full-pull prune race (gotcha
#35) and a refresh nudge dropped by a throttle (gotcha #6). Both are fixed.

**Known limitations, deferred:**
1. **Hiding is by path.** Renaming or moving a hidden folder in the app does
   not update `hidden_folders`, so the folder becomes visible to agents
   (fail-open). Fix: rewrite scope entries on folder rename/move, and flag
   hidden entries that match no folder in Settings.
2. **MCP roots are deprecated** (SEP-2577; `rmcp` warns on `list_roots`).
   Project detection already falls back to the agent passing `project`;
   when clients drop roots, the hook-side `brief --cwd` path is unaffected.
3. **Sync churn:** each `remember` rewrites the page, `Index` and `Log`
   (three Gmail insert+trash pairs). If Apple sync wedges recur, debounce
   the Index and roll the Log by month.
4. **Unicode normalization:** `normalize` folds case and whitespace, not
   NFC/NFD, so composed and decomposed spellings of one title make two
   pages (gotcha #30's territory). Needs `unicode-normalization`.
5. Git submodules resolve to the superproject's name; the workspace lock
   lives in the user cache dir, not beside the DB.
