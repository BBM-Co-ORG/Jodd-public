## 1. แนวคิด

Jodd ถูกออกแบบตามแพทเทิร์น **"LLM Wiki"** ของ Karpathy
(ดู [LLM-WIKI-GRAPHIFY-ROADMAP.md](LLM-WIKI-GRAPHIFY-ROADMAP.md)): แทนที่จะให้ AI
ไปอ่านแหล่งดิบใหม่ทุกครั้งที่ถาม ให้ความรู้ **สะสมเป็นหน้า wiki ที่เชื่อมกัน**
แล้วถามจาก wiki นั้น ในทางปฏิบัติแบ่งเป็น 4 ชั้น:

```
 ชั้น            อยู่ที่ไหนใน Jodd                       ใครเขียน
 ─────────────── ────────────────────────────────────── ──────────────
 ① แหล่งดิบ      บล็อก "Source (verbatim)" ท้ายโน้ต      ระบบเก็บให้อัตโนมัติ
 ② โน้ตย่อย      ผลของ Key points / Summarize / Transcript  AI ร่าง → คุณแก้
 ③ โน้ตความเข้าใจ โน้ตที่คุณเขียนเองด้วยคำของตัวเอง + [[ลิงก์]]  คุณ
 ④ Hub / ผลงาน   โน้ตสารบัญหัวข้อ, outline, บทเรียน, บทหนังสือ     คุณ (+ AI ช่วย)
```

**กติกาสำคัญ:** ชั้น ① และ ② สร้างง่าย จึงสะสมเร็วมาก แต่ความรู้จริงอยู่ที่ชั้น ③ และ ④
ถ้าคุณแค่ ingest อย่างเดียว Jodd จะกลายเป็นกองคลิปสรุปที่ไม่ได้ใช้

Jodd มี 4 แกนให้ทำงานกับชั้นเหล่านี้:

| แกน | เครื่องมือ |
|---|---|
| **เก็บ** (Capture) | Share to Jodd, Cmd/Ctrl+N, Extract modal |
| **ย่อย** (Distill) | Key points, Summarize, Transcript, Expand bullets, Action items |
| **เชื่อม** (Connect) | `[[wikilink]]`, `#tag`, "Link into wiki", "Suggest folder", Connections panel/graph |
| **ใช้** (Retrieve & Apply) | ค้นหา (FTS), Ask Jodd, jodd-mcp ให้ agent อื่นใช้ความรู้ |
| **ดูแล** (Maintain) | Organize, Orphaned, Stale, Extracts view |

## 2. ตั้งค่าครั้งแรก

| # | ทำอะไร | อยู่ที่ไหน | ทำไมต้องทำ |
|---|---|---|---|
| 1 | ตั้ง **LLM provider ระดับแอป** | App settings → "LLM provider" | **Ask Jodd ใช้ provider ตัวนี้ตัวเดียว** — ตั้งเฉพาะระดับบัญชีไม่พอ |
| 2 | ให้บัญชีใช้ provider นั้น | Account settings → "Use app default" หรือติ๊ก "Also use for Extract and auto-link on accounts with no provider of their own" | Extract/Summarize ฯลฯ ใช้ provider ระดับบัญชี |
| 3 | ติ๊ก "Allow this account’s data in Jodd-managed AI" | Account settings | ถ้าไม่ติ๊ก AI workflow ของบัญชีนั้นจะถูกปฏิเสธ |
| 4 | **เปิด "Automatically suggest folders and related links"** | App settings → "AI limits and automatic enrichment" | **ค่าเริ่มต้นปิด** — ถ้าไม่เปิด หลัง Extract จะไม่มีการเสนอโฟลเดอร์/ลิงก์ให้อัตโนมัติ ทุกโน้ตจะกองอยู่ใน Inbox |
| 5 | ตั้ง Share to Jodd | App settings → "Share to Jodd" (macOS: "Add to Share menu", bookmarklet; Android: Share sheet) | ลดแรงเสียดทานในการเก็บ — ยิ่งเก็บง่ายยิ่งได้ใช้ |
| 6 | (ถ้าใช้ Claude Code) เปิด Agent workspace | App settings → "Agent workspace" → "Enable agent workspace" + ซ่อนโฟลเดอร์ส่วนตัวใน "Hidden from agents" | ให้ agent อ่าน/จำความรู้ของคุณข้ามโปรเจกต์ (desktop เท่านั้น) |

> **Provider:** "Agent CLI (headless)" (claude, codex, gemini, thclaws …) ใช้ได้บน
> desktop เท่านั้น บน Android ต้องใช้ "Custom endpoint (OpenAI-compatible)"
> ปุ่ม "Test connection" เรียกโมเดลจริงหนึ่งครั้ง (เสียโควตา)

## 3. Workflow อ้างอิง

### 3.1 เก็บ (Capture)

**Share to Jodd** — แชร์ลิงก์/ข้อความจากเบราว์เซอร์หรือแอปอื่น → หน้าต่าง "Shared to Jodd"
- "Save" = บันทึกตามที่แชร์มาลง `Notes/Inbox` ทันที (ไม่ใช้ AI)
- "Or make a note with AI" = เลือกโหมด AI (5 แบบด้านล่าง) แล้วส่งเข้า Extract modal
- "Discard" = ทิ้ง
- ข้อจำกัด: คิวรออยู่ในหน่วยความจำ 20 รายการ (ปิดแอปแล้วหาย), ยังไม่รองรับรูป/ไฟล์, ยังไม่มี hotkey quick capture แบบ global

**โน้ตใหม่ปกติ** — Cmd/Ctrl+N

### 3.2 ย่อย (Distill) — Extract modal

**เปิด:** ปุ่มหลอดไฟ 💡 ที่หัวบัญชีใน sidebar ("Ingest a source into …") หรือ **Cmd/Ctrl+Shift+L**

**เลือกแหล่ง:** "Paste text" (วางข้อความ/ลิงก์) หรือ "Pick existing note" (ใช้โน้ตที่มีอยู่)
**เลือกปลายทาง:** "New note" หรือ "Append to existing note" (ต่อท้ายโน้ตเดิม ไม่แก้ของเดิม)

| โหมด | ใช้เมื่อ | ได้อะไร |
|---|---|---|
| **Key points** (= Extract) | บทความ, วิดีโอ, บันทึกการคุย — อยากได้ "บทเรียน" | หัวข้อย่อยเป็นข้อๆ + `#tag` + บล็อก Source |
| **Summarize** | อยากได้ภาพรวมสั้น | สรุปเป็นย่อหน้า |
| **Expand bullets** | มีโครงเป็นข้อๆ อยากขยายเป็นร้อยแก้ว | ร้อยแก้วจาก bullet — **มีประโยชน์มากตอนเขียนหนังสือ** |
| **Transcript** | อยากได้บทพูดเต็ม (YouTube) | "Clean" = AI เกลาแต่เก็บครบ; raw ได้เฉพาะลิงก์ |
| **Action items** | บันทึกประชุม | ร่าง "Decisions / Actions (`- [ ]`) / Unresolved / Evidence" ต้องกด "Review draft" ก่อนบันทึก (ข้อความเท่านั้น ≤ 24,000 ตัวอักษร) |

**วางลิงก์ (URL ingest):** วางลิงก์เว็บหรือ YouTube แล้ว Jodd จะแสดงรายการ "Sources from links"
ให้ติ๊กเลือก (สูงสุด **8 ลิงก์**/ครั้ง, ต้องเลือก "New note"). ถ้าเคย ingest ลิงก์นั้นแล้วจะเห็น
ป้าย "already in …" และคำเตือน "Already extracted from …" (เตือนเฉยๆ ไม่บล็อก — กด "Continue anyway" ได้)

**ผลลัพธ์ทุกโหมด:** โน้ตใหม่ลง **`Notes/Inbox`** + บรรทัด `#tag` (AI พยายามใช้แท็กที่บัญชีมีอยู่แล้ว)
+ บล็อก "Source (verbatim)" ที่เก็บต้นฉบับไว้ ถ้าเปิด automatic enrichment จะได้ chip
"→ โฟลเดอร์" ให้กด "Move" / "Keep here" และลิงก์ "Related: [[…]]" อัตโนมัติ

**"Re-extract"** (คลิกขวาที่โน้ตที่มี Source) — ย่อยแหล่งเดิมใหม่เป็นโน้ตใหม่ ใช้ตอนเปลี่ยนโหมด/โมเดล
โดยไม่ต้องหาแหล่งใหม่

### 3.3 เชื่อม (Connect)

| เครื่องมือ | วิธีใช้ | หมายเหตุ |
|---|---|---|
| `[[wikilink]]` | พิมพ์ `[[` ใน editor → เลือกโน้ต | เปลี่ยนชื่อโน้ตแล้วลิงก์ตามให้; ลิงก์ข้ามบัญชีไม่ได้; บน iPhone เห็นเป็นข้อความธรรมดา (กดไม่ได้) |
| `#tag` | พิมพ์ในเนื้อหา หรือช่อง "add tag…" | แท็กอยู่ในเนื้อหาจึง sync ไป Apple Notes ได้; sidebar "Tags" กรองแบบ AND/OR, เปลี่ยนชื่อ/ลบทั้งบัญชีได้ |
| **"Link into wiki"** | คลิกขวาโน้ต | AI หาโน้ตที่เกี่ยวข้อง (คำค้น ≤ 8 → ผู้สมัคร ≤ 20 → AI ตัดสิน) เพิ่ม "Related: [[…]]" และเสนอให้ไปเติมลิงก์กลับในโน้ตอื่น ("Add to N notes") |
| **"Suggest folder"** | คลิกขวาโน้ต | AI เลือกจากโฟลเดอร์**ที่มีอยู่แล้ว**เท่านั้น — ต้องสร้างโครงโฟลเดอร์ก่อนถึงจะได้ผล |
| Connections panel | ใต้ editor | "→ Links to", "← Linked from", "Sources (N)" (ทุก URL ในโน้ตกลายเป็น source อัตโนมัติ) |
| "Connections graph" | ปุ่มบน toolbar editor | กราฟรัศมี **1 ชั้น** ของโน้ตนี้ คลิกเพื่อไปต่อได้ |

### 3.4 ใช้ (Retrieve & Apply)

**ค้นหา** — FTS5 แบบ trigram ค้นภาษาไทยแบบ substring ได้ (คำค้นควรยาว ≥ 3 ตัวอักษร)
เลือก scope บัญชี/โฟลเดอร์/ทุกบัญชีได้

**Ask Jodd** — ไอคอนแชตท้าย sidebar ("Ask Jodd about your notes")
- Scope: "This account" / "This folder and below" / "All accounts"
- กลไก: คัดผู้สมัคร ≤ 400 โน้ต → AI เลือก ≤ **12 โน้ต** → ตอบ พร้อม citation `[[…]]` ที่กดเปิดโน้ตได้
- หน้าต่างแสดง "N in scope → N considered → N read" — ถ้าตัวเลขน้อย แปลว่าคำถามไม่ตรงคำในโน้ต ลองเปลี่ยนคำ
- **คำตอบไม่ถูกบันทึก** ปิดหน้าต่างแล้วหาย — ถ้าคำตอบดี ต้อง copy ไปเป็นโน้ตเอง

**jodd-mcp (ให้ agent ใช้ความรู้ของคุณ)** — Claude Code / agent อื่นเรียก `search_notes`,
`read_note`, `note_connections`, `list_tasks` และเขียนผ่าน `remember`, `create_note`,
`update_note` (เฉพาะโฟลเดอร์ที่อนุญาต; โฟลเดอร์ที่ซ่อน agent มองไม่เห็นเลย)
ถ้าตั้ง "Session briefing for Claude Code" ไว้ ทุก session จะได้ About me + หน้าโปรเจกต์ + Log ล่าสุดอัตโนมัติ

### 3.5 ดูแล (Maintain)

| มุมมอง (sidebar → Views) | แสดงอะไร | ใช้ทำอะไร |
|---|---|---|
| **Orphaned** | โน้ตที่ไม่มีใครลิงก์เข้า | หาเกาะที่ยังไม่ต่อเข้าความรู้ |
| **Stale** | ไม่ถูกแก้ ≥ 30 วัน | ทบทวน / ตัดทิ้ง / รวม |
| **Extracts** | ทุกโน้ตที่มี Source block ไม่ว่าอยู่โฟลเดอร์ไหน | ดูชั้น ② ทั้งหมด |
| **Organize** (desktop) | "Find problems" → **Duplicates** (เหมือน ≥ 60%) / **Misfiled notes** (ค้างใน Notes หรือ Inbox ≥ 24 ชม.) / **Secrets in notes** | กด "Preview" → "Approve" ทีละใบ; สแกนละไม่เกิน 8 ข้อเสนอต่อประเภท |

## 4. Use case A — วงจรการเรียนรู้

เป้าหมาย: ทุกสิ่งที่อ่าน/ดู ต้องเดินจากชั้น ① ไปถึงชั้น ③ ให้ได้ และชั้น ③ ต้องถูก**ใช้**

### 4.1 โครงโฟลเดอร์แนะนำ

```
Notes/
├── Inbox/                 ← ระบบใส่ให้เอง อย่าทิ้งของไว้นานเกิน 1 สัปดาห์
├── Areas/                 ← เรื่องที่ศึกษาต่อเนื่อง ไม่มีวันจบ
│   ├── AI-Agents/
│   ├── Business/
│   └── Security-GRC/
├── Projects/              ← มีปลายทาง มีวันจบ (คอร์ส, หนังสือ, ระบบ)
├── Library/               ← ชั้น ② ที่ย่อยแล้วแต่ยังไม่ได้เขียนต่อ (optional)
└── Archive/
```

สร้างโครงนี้ก่อน เพราะ "Suggest folder" และ Organize เสนอได้เฉพาะโฟลเดอร์ที่**มีอยู่แล้ว**

### 4.2 จังหวะ: รายวัน / รายสัปดาห์ / รายเดือน

**รายวัน (5–10 นาที) — เก็บและย่อย**
1. เจอของดี → Share to Jodd → เลือก **Key points** (บทความ/วิดีโอ) หรือ **Save** เฉยๆ ถ้ายังไม่แน่ใจ
2. อ่านโน้ตที่ AI ทำให้ **1 รอบ** — ลบข้อที่ไม่จริง/ไม่สำคัญ, แก้แท็กให้ตรงคำศัพท์ของคุณ
3. เพิ่ม **บรรทัดเดียวด้วยคำของตัวเอง** ที่หัวโน้ต: "ทำไมเรื่องนี้สำคัญกับฉัน / จะเอาไปใช้ที่ไหน"
   — บรรทัดนี้คือสิ่งที่ทำให้ Ask Jodd หาเจอในอนาคต และเป็นจุดเริ่มของชั้น ③

**รายสัปดาห์ (30–45 นาที) — เชื่อมและเขียน (สำคัญที่สุด)**
1. เปิด **Organize** → "Find problems" → จัดการ Misfiled / Duplicates
2. เปิด `Notes/Inbox` ทีละโน้ต: "Suggest folder" → "Move"; "Link into wiki" → รับลิงก์ที่สมเหตุสมผล
3. เปิด **Orphaned** — โน้ตไหนยังไม่มีลิงก์เข้า ให้ไปใส่ไว้ใน Hub ของหัวข้อนั้น
4. **เขียนโน้ตความเข้าใจ (ชั้น ③) อย่างน้อย 1 โน้ต**: เลือกแนวคิดที่เจอซ้ำหลายแหล่งในสัปดาห์นี้
   เขียนเป็นคำของคุณเอง 1 ไอเดีย/โน้ต, ชื่อโน้ตเป็น**ประโยคข้อสรุป** (เช่น
   "Agent ที่ดีต้องให้มนุษย์ตรวจก่อน commit การกระทำที่ย้อนไม่ได้") แล้ว `[[ลิงก์]]` ไปยังโน้ตชั้น ② ที่เป็นหลักฐาน
5. อัปเดต **Hub note** ของหัวข้อ (ดู 4.3)

**รายเดือน (1 ชม.) — ทดสอบความรู้และขยาย**
1. Ask Jodd แบบ "This folder and below" ใน Area หนึ่ง ด้วยคำถามประเภท:
   - "สรุปสิ่งที่ฉันรู้เกี่ยวกับ X พร้อมบอกว่าโน้ตไหนขัดแย้งกัน"
   - "อะไรที่ฉันยังไม่รู้เกี่ยวกับ X จากที่จดไว้ มีช่องว่างตรงไหน"
   - "ถ้าต้องสอนเรื่อง X ใน 10 นาที ควรเริ่มจากโน้ตไหน"
2. คำตอบที่ดี → copy ไปเป็นโน้ตใหม่ (Ask ไม่บันทึกให้) แล้วลิงก์เข้า Hub
3. ช่องว่างที่ Ask ชี้ → กลายเป็น "รายการที่ต้องหาอ่านต่อ" ใน Hub → วงจรรอบถัดไป
4. เปิด **Stale** — โน้ตเก่าที่ยังจริงอยู่ ให้ลิงก์เข้า Hub; ที่ล้าสมัยให้ย้าย Archive

### 4.3 Hub note (Map of Content) — หัวใจของการ "ค่อยๆ expand"

หนึ่ง Hub ต่อหนึ่งหัวข้อใน Areas, ปักหมุด ("Pin") ไว้ ตัวอย่างโครง:

```
AI Agents — Hub
#hub #ai-agents

ฉันเชื่อว่า (ข้อสรุปปัจจุบัน — แก้ได้เรื่อยๆ)
- [[agent-ต้องมี-human-checkpoint-…]]
```

## 5. Use case B — Research → คอร์ส / หนังสือ

### 5.1 โครงโปรเจกต์

```
Notes/Projects/<ชื่อหนังสือหรือคอร์ส>/
├── 00 Brief          ← 1 โน้ต: ผู้อ่านคือใคร, หลังอ่าน/เรียนจบต้องทำอะไรได้, ขอบเขต, ไม่ครอบคลุมอะไร
├── 10 Sources        ← ชั้น ② : ผลการ ingest ทุกแหล่ง (Key points / Transcript)
├── 20 Notes          ← ชั้น ③ : โน้ตความเข้าใจ 1 ไอเดีย/โน้ต, ชื่อเป็นข้อสรุป
├── 30 Outline        ← 1 โน้ต outline หลัก + 1 โน้ตต่อบท/โมดูล
├── 40 Drafts         ← ร่างแต่ละบท
└── 50 Assets         ← ตัวอย่าง, แบบฝึกหัด, quiz, สไลด์โน้ต
```

### 5.2 ขั้นตอน

**ขั้น 1 — Brief (ก่อนหาแหล่ง)**
เขียน `00 Brief` เป็นคำถามวิจัย 3–7 ข้อ เช่น "SME ไทยใช้ AI agent ทำงานแทนคนได้ที่ไหนบ้าง"
คำถามเหล่านี้คือตัวกรองว่าแหล่งไหนควร ingest และจะกลายเป็นหัวบท

**ขั้น 2 — รวบรวมแหล่ง (Research)**
- วางลิงก์ทีละ ≤ 8 ใน Extract modal → **Key points** (หรือ **Transcript** "Clean" ถ้าต้องอ้างคำพูด)
- ย้ายผลจาก Inbox ไป `10 Sources` (หรือใช้ "Append to existing note" สะสมเข้าโน้ตธีมเดียวกัน)
- **แท็กตามคำถามวิจัย** เช่น `#rq1` `#rq2` และชนิดเนื้อหา `#claim` `#example` `#stat` `#quote` `#counterpoint`
- ใส่บรรทัดอ้างอิงด้วยมือที่หัวโน้ต: `ผู้เขียน · ปี · ชื่อ · URL · (นาทีที่/หน้า)` — Jodd เก็บ URL ให้แต่**ไม่มี** metadata บรรณานุกรม (ดู Gap)

**ขั้น 3 — สังเคราะห์ (Synthesis)**
- ต่อคำถามวิจัย: Ask Jodd scope "This folder and below" ที่โฟลเดอร์โปรเจกต์ ถาม
  "จากแหล่งที่มี ตอบ RQ1 พร้อมอ้างโน้ต และบอกข้อที่แหล่งขัดกัน" → copy คำตอบเป็นโน้ตใน `20 Notes`
- เขียนโน้ตชั้น ③ ด้วยตัวเอง: 1 ข้อสรุป/โน้ต, ลิงก์ไปหลักฐานใน `10 Sources`
- ใช้ "Link into wiki" กับโน้ต ③ แต่ละใบ เพื่อดึงโน้ตเก่าใน Areas ที่เกี่ยวข้องเข้ามา
  (นี่คือจุดที่ความรู้สะสมจาก Use case A ตอบแทน)

**ขั้น 4 — Outline**
`30 Outline/Outline` เป็นลำดับบท แต่ละบทเป็น `[[ลิงก์]]` ไปโน้ตบท และโน้ตบทมีลำดับย่อหน้า
เป็น `[[ลิงก์]]` ไปโน้ต ③

```
บทที่ 3 — เมื่อไหร่ควรให้ agent ทำแทน
วัตถุประสงค์: ผู้อ่านแยกงานที่ย้อนกลับได้/ไม่ได้ และออกแบบ checkpoint ได้
1. เปิดด้วยเรื่องเล่า  [[gpt-สั่งงาน-hermes-…]]
2. ข้อสรุปหลัก        [[agent-ต้องมี-human-checkpoint-…]]
3. หลักฐาน           [[…]] [[…]]
4. ข้อโต้แย้ง          [[…]] #counterpoint
5. แบบฝึกหัด          (ยังไม่มี → งานต้องทำ)
```

ตอนนี้ Connections panel ของโน้ตบทจะบอกทันทีว่าบทนี้มีวัตถุดิบกี่ชิ้น และ Orphaned ใน
`20 Notes` คือไอเดียที่ยังไม่ได้ใส่บทไหน

**ขั้น 5 — ร่าง (Drafting)**
- เขียนโครงบทเป็น bullet → Extract modal "Pick existing note" → **Expand bullets** →
  ได้ร่างร้อยแก้วใหม่ (บันทึกเป็นโน้ตใหม่ ร่างเดิมไม่ถูกแก้) → ย้ายเข้า `40 Drafts` แล้วเกลาเอง
- งานร่างยาว: ใช้ Claude Code + jodd-mcp (`read_note` อ่านโน้ตบทและโน้ตที่ลิงก์ทั้งหมด)
  แล้วเขียนร่างเป็นไฟล์ Markdown นอก Jodd — เหมาะกว่าการร่างทั้งบทใน editor ของโน้ต

**ขั้น 6 — ทำเป็นคอร์ส**
ใช้ Hub/Outline เดิม แค่เปลี่ยนหน่วย: บท → โมดูล, หัวข้อย่อย → บทเรียน (lesson) ละ 5–10 นาที
แต่ละบทเรียนควรมี: วัตถุประสงค์ 1 ข้อ, ไอเดียหลัก 1 ข้อ (= โน้ต ③ 1 ใบ), ตัวอย่าง (`#example`),
แบบฝึก/quiz (`50 Assets`) ถ้าแหล่งเป็นวิดีโอ ใช้ Transcript "Clean" เพื่อดึงคำพูดที่จะอ้างหรือดัดแปลง

**ขั้น 7 — ส่งออก**
ยังไม่มีปุ่ม export (ดู Gap #1) ทางเลี่ยงตอนนี้: ให้ Claude Code อ่านผ่าน jodd-mcp `read_note`
ตามลำดับใน Outline แล้วประกอบเป็นไฟล์ `.md`/`.docx` หรือถ้าบัญชีเป็น **Local Folder / SSH**
โน้ตเป็นไฟล์บนดิสก์อยู่แล้ว (`.eml` / Markdown) ให้เครื่องมืออื่นอ่านต่อได้

## 6. Practice และ convention

**การเขียนโน้ต**
1. **1 ไอเดีย/โน้ต** สำหรับชั้น ③ — ลิงก์ได้แม่นกว่า, Ask Jodd เลือกได้แม่นกว่า (มันอ่านได้ทีละ ≤ 12 โน้ต)
2. **ชื่อโน้ตเป็นข้อสรุป** ไม่ใช่หัวข้อ ("X ทำให้ Y เพราะ Z" ดีกว่า "เรื่อง X")
3. **เขียนด้วยคำของตัวเองอย่างน้อย 1 บรรทัด** ในทุกโน้ตที่ AI สร้าง — ถ้าไม่มีอะไรจะเขียน แปลว่าไม่ควรเก็บ
4. **ลิงก์อย่างน้อย 1 ลิงก์**ก่อนออกจาก Inbox (ไป Hub หรือโน้ตที่เกี่ยวข้อง)
5. โน้ตยาวมาก (> 20,000 ตัวอักษร) Ask Jodd จะตัดเหลือ 20,000 — แยกเป็นหลายโน้ตแทน

**แท็ก** — แท็กเป็นแกนตั้งฉากกับโฟลเดอร์ ใช้สำหรับ "ชนิด" และ "สถานะ" ไม่ใช่หัวข้อซ้ำกับโฟลเดอร์
- ชนิด: `#hub` `#claim` `#example` `#stat` `#quote` `#counterpoint` `#how-to`
- สถานะ: `#seed` (เพิ่งเก็บ) → `#growing` (มีความเข้าใจตัวเองแล้ว) → `#evergreen` (พร้อมใช้สอน/เขียน)
- โปรเจกต์: `#book-xxx-ch03`, `#rq1`
- ใช้ sidebar Tags แบบ AND เช่น `#book-xxx` AND `#seed` = วัตถุดิบหนังสือที่ยังไม่ได้ย่อย
- Extract พยายามใช้แท็กเดิมของบัญชี — คำศัพท์แท็กที่สะอาดจะทำให้ AI แท็กได้สม่ำเสมอขึ้นเอง

**การเก็บ**
- **เช็ก "already in …" ก่อน ingest ซ้ำ** — ingest วิดีโอเดียวกันสองรอบจะได้โน้ตซ้อน
  (เช่น Key points 2 ใบ + Transcript 1 ใบ ใน Inbox)
  ให้ใช้ "Append to existing note" หรือ "Re-extract" แทนการ ingest ใหม่ แล้วรวมด้วย Organize → Duplicates
- เก็บ Transcript เฉพาะแหล่งที่จะ**อ้างคำพูด**จริง นอกนั้น Key points พอ (Source block เก็บต้นฉบับให้อยู่แล้ว)

**ความเป็นส่วนตัว**
- โฟลเดอร์ที่มีข้อมูลลูกค้า/ความลับ → ติ๊กใน "Hidden from agents" (agent มองไม่เห็นเลย)
- **ระวัง:** เปลี่ยนชื่อโฟลเดอร์ที่ซ่อนแล้วจะ**ไม่ซ่อนอีกต่อไป** (ซ่อนตาม path) — ติ๊กใหม่ทุกครั้งที่ rename
- Organize → "Secrets in notes" สแกนหา API key/รหัสผ่านที่เผลอวาง

**Apple Notes**
- `#tag` และข้อความ sync ไป iPhone ได้; `[[ลิงก์]]` บน iPhone เป็นข้อความธรรมดา; Pin ไม่ sync ไปบัญชี Microsoft
- ถ้าจะทำงานวิจัยใหญ่ ให้เลือกบัญชีเดียวเป็นบ้านของโปรเจกต์ — ลิงก์และ Link into wiki ข้ามบัญชีไม่ได้

| R8 | ลิงก์/Ask/Link into wiki ข้ามบัญชีไม่ได้; ย้ายโน้ตข้ามบัญชียังเป็น stub | roadmap #6 | ความรู้จากบัญชีอื่นเข้าโปรเจกต์ไม่ได้ | เลือกบัญชีเดียวเป็นบ้านของงานวิจัย |
| R9 | ไม่มีการตรวจข้อขัดแย้งระหว่างโน้ตอัตโนมัติ | Organize M2 เลื่อนไว้ | ข้อมูลขัดกันในหนังสือหลุดไปได้ | ถาม Ask Jodd ให้ "ระบุข้อที่แหล่งขัดกัน" ทุกบท |

### 7.3 ถ้าจะพัฒนาต่อ — ลำดับที่ผมแนะนำ

เรียงตาม (ผลต่อสอง use case) ÷ (แรงที่ต้องใช้) โดยอิงสิ่งที่โค้ดมีอยู่แล้ว:

1. **"Save as note" ใน Ask Jodd** — เล็กมาก: มี `save_workflow_envelope` และ citation `[[…]]`
   อยู่แล้ว ทำให้ Ask กลายเป็นเครื่องผลิตชั้น ③ (ปิด L1)
2. **Export โฟลเดอร์ → Markdown bundle** (ทำเป็น OKF ไปเลย) — แปลง `[[…]]` เป็นลิงก์สัมพัทธ์,
   `cites` เป็น `# Citations`, สร้าง `index.md`; บวกโหมด "compile ตามลำดับลิงก์ใน Outline note"
   (ปิด R1 และได้ backup)
3. **Source metadata** — ขยาย Source block ให้เก็บ ผู้แต่ง/ปี/ชื่อเรื่อง/timestamp ที่ LLM ดึงได้ตอน ingest
   (ปิด R2; ส่งต่อไป export ข้อ 2 ได้ทันที)
4. **PDF / ไฟล์ข้อความ ingest** — ผ่าน Extract modal และ Share (ปิด R3)
5. **Review queue** — smart folder แบบ "ทบทวนวันนี้" จาก `#review` + ระยะห่างแบบ SM-2 ง่ายๆ
   ต่อยอดจาก Stale ที่มีอยู่ (ปิด L2)
6. **Templates** (Hub / Brief / Chapter) และ **global graph** — มีประโยชน์แต่รอได้

> ข้อ 1–3 ทำแล้ว Jodd จะครบวงจร "เก็บ → ย่อย → เชื่อม → สังเคราะห์ → **ส่งออก**"
> ซึ่งตอนนี้ขาดแค่ปลายทางสุดท้าย
