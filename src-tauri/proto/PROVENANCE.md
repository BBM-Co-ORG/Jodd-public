# Where these `.proto` files came from

Apple's Notes note document — the thing behind a CloudKit record's
`TextDataEncrypted` — is an undocumented protobuf. These three files are its
schema. They are **data, not code**: `prost` compiles them directly, and
nothing in them was written by hand or inferred from a sample.

## Upstream

[`icloud-md`](https://www.npmjs.com/package/icloud-md) v0.6.2, by Adam

Attribution is the only obligation, and this file is it.

> **Reuse `proto/*.proto` verbatim (454 lines).** These are the crown jewels
> and they are *data*: `prost` compiles them in Rust with no translation.

## How they were recovered, and why that matters

**The npm package does not ship `proto/`.** Its `files` list publishes `dist/`
only, so the `.proto` sources that `docs/PRIOR-ART.md` describes are visible in
the upstream git repository but absent from the artifact. What `dist/` *does*
carry is `dist/notes/gen/*_pb.js`, generated by `protoc-gen-es`, and a
Protobuf-ES generated module embeds the **serialized `FileDescriptorProto`** of
its source file as a base64 string:

```js
export const file_versioned_document = fileDesc("Chh2ZXJzaW9uZWRfZG9jdW1lbnQucHJvdG8...");
```

That descriptor is `protoc`'s own parse of the original `.proto` — the compiler
output, not a copy of the text. Decoding it back to `.proto` source therefore
recovers the schema exactly rather than reconstructing it from note samples,
which is the difference between ground truth and the "tidy but wrong" rule
CLAUDE.md's gotcha #11 warns about.

The recovery was checked, not assumed: each decoded `FileDescriptorProto` was
**re-serialized and compared byte-for-byte** against the base64 blob it came
from before any `.proto` text was emitted. Field numbers, labels
(`required` / `optional` / `repeated`), types, nesting and defaults are all
carried by the descriptor, so the emitted text is a faithful view of it.

Comment text is the one thing a descriptor does not carry (upstream compiles
without `--include_source_info`), so these files have no comments where the
originals may. Nothing semantic is lost.

## What each file is for

| File | Package | Used by |
|---|---|---|
| `versioned_document.proto` | `versioned_document` | The outer wrapper of every mergeable payload. `Document.version[0].data` holds the real document. |
| `topotext.proto` | `topotext` | A **note body**. `String.string` is the visible text; `String.attributeRun` is the formatting M1 does not decode. |
| `crdt.proto` | `CRDT` | A **table** (`MergeableDataEncrypted`). Unused in M1; vendored because it is part of the same schema set and M2 needs it. |

The M1 read path is exactly:

```
TextDataEncrypted → base64 → gzip *or* zlib → versioned_document.Document
                  → version[0].data → topotext.String → .string
```

## Keeping them honest

`src-tauri/src/backend/icloud/gen/` holds Rust generated from these files and
is **committed**, so no `protoc` runs during a build. `icloud_gen_is_current`
regenerates and diffs, so a `.proto` edit without regenerating cannot land.
See that test for how to update.

Upstream drift is a separate question this repo cannot answer automatically:
if `icloud-md` changes its schema, nothing here notices. Re-run the recovery
against a newer `dist/notes/gen/*_pb.js` when that matters.
